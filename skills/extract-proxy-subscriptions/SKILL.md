# 代理软件订阅提取

把已有账号或客户端配置变成可验证、可维护的标准订阅。先确定数据从哪里来、由什么身份取得，再考虑格式转换。只处理用户授权的软件、账号、会话和目标环境。

## 确定入口

根据已有材料选择最短路径，不要求每次重做逆向：

- 已有可用订阅或解密后的连接配置：先检查字段和格式，直接复用项目中的导出器。
- 已安装并登录的客户端：定位它实际使用的配置、API 地址和会话，区分缓存导出与在线批量导出。
- 只有安装包或二进制：先静态识别 UI、核心、协议和加密格式。此时可以回答可行性，不能宣称拿到了真实线路。
- 已经导出但连接失败：沿验证链找失败层，不先重写解密器或随意换节点入口。
- 请求自动刷新或 VPS 分发：先复用提取算法，再处理身份、缓存和发布边界；提取请求本身不授权部署或重置链接。

已有授权覆盖的常规读取、修复和验证继续执行。缺少材料时只问当前步骤必需的安装包/配置位置、软件版本或目标格式；密码和 token 通过本地私有文件、交互输入或现有安全存储传递。

## 分析与实现

1. **绑定样本。** 记录版本、平台和输入哈希；读项目现有说明、提取器、测试和失败记录。看到字段名或二进制字符串只算线索，不算链路已证实。
2. **画出最小数据链。** UI → 核心 → 配置/接口 → 身份/会话 → 连接参数 → 导出。把用户账号、设备身份、会话 token 和订阅读取 token 分开。
3. **确认协议与边界。** 软件里的 W/X 等名称不是标准协议名。线路目录通常只有名字和位置，完整凭据可能要在连接时按线路请求。
4. **按证据还原格式。** 确定编码层数、算法、key/IV 来源、nonce/tag 布局和字段映射。验证认证标签或填充以及解密后的结构，不能把“能解码”当作成功。
5. **复用一个转换实现。** 本地、自动刷新和服务器调用同一导出器。逐项保留传输、TLS、SNI、WebSocket path/headers 和 ID 语义，不机械套用其他客户端的模板。
6. **补上真实边界验证。** 先解析和字段一致性，再检查真实 DNS、协议握手、HTTP 转发和规则命中。定位失败层后只修正该层。
7. **保存可续跑的证据。** 原始敏感文件留在私有目录；公开记录只保留版本、结构、数量、哈希、脱敏结果和未验证项。

## 不应丢失的判断

- HTTP 200、解密成功、配置解析成功、DNS 正常、代理握手和最终转发分别提供不同证据。
- 系统 TUN 的 Fake-IP 响应不能证明真实入口存在。`198.18.0.0/15` 等合成地址需单独识别。
- 不给全部 `locations` 条目套用同一个缓存中的 token/path，除非接口或客户端行为证明它们共享这些参数。
- 账号密码摘要仍是凭据；设备随机密码不是用户密码。保留密码中的空格，不擅自 trim 或重复散列。
- 设备名额、会员期限和会话期限是不同状态。设备已满或凭据拒绝时停止相应重试；HTTP 429 停止整个批次的后续请求，并记录 Retry-After 或其他恢复条件。不能通过反复注册、切换地址或删除其他设备来“修复”。
- 固定设备身份在请求前持久化，失败重试复用该身份。会话更新必须原子保存；批量中途换会话时重建完整结果，不能混合旧、新凭据。
- 客户端内置的通用协议常量不等同于用户秘密。保留必要实现，同时不把账号、设备、订阅或节点凭据放进源码、日志和示例。
- 分别记录当前去重目录数、参数成功数和失败数。部分请求失败不能解释成上游目录缩减，也不能标成完整订阅；首次失败且无旧缓存时明确没有已验证的完整结果。不要把某次采样数量写死成长期验收标准。

## 完成标准

按用户请求的层次交付：仅静态分析提供版本绑定的链路和待证实点；实际提取提供可导入文件及脱敏摘要；排错给出复现、失败层和修复验证；分发给出已授权目标、缓存与访问检查。

说明实际验证了哪些节点、网络条件和目标。选择一个出口证明规则生效，不能表述为全部线路稳定可用。不把未运行的 GUI 导入、协议兼容性、长期续期或完整出口测速写成已完成。

在包含本项目代码的工作区，可复用根目录飞鸟导出脚本、`leapvpn/` 和 `vps-service/`。离开本项目时先定位当前实现；本 skill 不依赖某个开发者的目录、域名、密钥或在线服务器。
