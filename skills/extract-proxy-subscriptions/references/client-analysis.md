# 客户端分析：从样本到数据链

适用于未知客户端或版本已变化的情形。已有经过验证的导出器时，先核对样本身份和受影响边界，不重做完整分析。

## 静态起点

记录安装包或核心的版本、平台、SHA-256 以及分析工具版本。优先列出和解包文件，不为获取结构而运行安装器。

常见分层及值得检查的证据：

| 层 | 常见材料 | 要回答的问题 |
| --- | --- | --- |
| UI | Electron ASAR、Next.js chunks、Flutter 资源 | 用户操作调用本机服务还是远端 API？ |
| 核心 | Go/PE/ELF、嵌入模板、模块信息 | 实际代理核心是什么，支持哪些协议？ |
| 设置 | JSON、二进制缓存、首选项、数据库 | 配置路径如何生成，文件是否真是明文？ |
| 身份 | 设备注册、账号绑定、会话结构 | 谁登录，凭据由谁产生，有效期属于哪一层？ |
| 连接 | 订阅接口、目录接口、连接时请求 | 哪一步才返回服务器、ID、传输与 TLS 参数？ |

`go version -m`、符号或函数表、UI 的 fetch/IPC 调用和模板字符串都是可用线索。Go 核心即使被剥离符号，也可能保留函数表。函数地址和文件偏移只对对应哈希的样本有效。

## 配置路径与加密

从客户端如何拼接路径、读取和写入配置入手。不要默认 `appsettings.json` 就是可直接解析的 JSON，也不要只因函数名称含 “AES256” 就确定实际密钥长度。

确认：

- 字符串使用 UTF-8、ASCII、十六进制还是 Base64；是否有多层包装。
- 模式是 CBC、GCM 等哪一种；CBC 的 IV、填充和 GCM 的 nonce/tag 长度。
- 密钥来自公开客户端常量、本机保护存储、账号派生值还是服务端。
- 加密读写路径是否互相印证；认证标签错误必须拒绝，不能继续解析随机明文。

先在一个被授权的样本上恢复结构，再用合成样本和篡改负例保护实现。输出只展示字段名、结构、计数和必要状态，不展示密码或完整连接凭据。

## API 与身份

把网页账户登录、设备注册/登录、账户绑定、会话续期、线路目录和连接参数请求分别记录。一个网站登录成功，不足以证明它的 token 可以用于代理连接。

对照客户端当前配置中的 base URL、请求方法、headers、参数和错误码。优先使用已验证的动态地址发现机制；不要把本次看到的 IP 永久硬编码。带凭据的请求不应跟随到未知目标的重定向。

需要验证真实认证时，复用用户授权的会话或通过明确的本地凭据入口操作。注册设备、绑定账号、同步到服务器及改变生产状态分别按当前授权执行。失败时区分密码错误、账号状态、设备名额、会话失效、HTTP 限流和网络错误。

## 最小输出

给出版本绑定的结论、最短数据链、哪些字段已经证实、哪些仍是推断，以及下一项能消除不确定性的检查。没有账户或登录态时，静态分析可以完成；真实线路导出继续标为未验证。
