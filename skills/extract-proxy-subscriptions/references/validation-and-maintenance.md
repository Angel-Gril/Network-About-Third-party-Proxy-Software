# 验证、刷新与分发

## 定位失败层

按最短证据链检查，发现失败层后再深入：

| 层 | 能证明什么 | 不能据此证明什么 |
| --- | --- | --- |
| HTTP 下载 | 取得响应体 | 响应是有效订阅、节点可用 |
| 解密与解析 | 编码、密码学与结构匹配 | 上游仍接受会话 |
| 参数对应 | 导出保留 ID、传输、TLS 等 | 网络能访问该入口 |
| DNS | 入口有真实解析 | 端口与出口正常 |
| 协议握手 | WS/TLS/VLESS 等路径建立 | 任意网站或全部线路可用 |
| HTTP 转发 | 选定出口能到指定目标 | 长期稳定、所有地区或流媒体解锁 |
| 规则命中 | 流量被选定规则分配 | 该出口所有请求都成功 |

不要通过反复相同测速筛选一次成功；保留失败，改变条件时说明在排除哪个假设。

## DNS 与受限入口恢复

Fake-IP DNS 返回合成地址时，应结合真实解析器或独立服务器核对 NXDOMAIN、A/AAAA 和错误类型。系统 `getaddrinfo` 有结果不能单独作为发布依据。

历史入口只在已有真实证据支持时用于恢复：新入口不能解析、同一账户的最后有效旧入口仍可解析、连接身份及端口/传输/TLS 等参数匹配。仅替换得到证实的 `server`，保留新配置的其他字段；没有匹配依据就保留旧缓存并报告失败。

这是一种受限恢复策略，不是把任意历史 IP 写回所有节点。先用独立核心验证恢复后的真实转发。

## 实际分流检查

使用独立工作目录、回环监听、临时端口和私有 controller secret，关闭测试核心的 TUN。第二个核心可能被用户已有 TUN 接管；出现不稳定时比较普通路径与显式物理网卡绑定，避免改动用户的全局代理设置。

选择一个已经确认能转发的出口，逐条覆盖当前规则类型和目标策略。自定义内网后缀可以用临时 hosts 与本机 HTTP 目标验证；公网请求用于验证实际转发。

- 同时检查规则类型、payload 和策略链。短连接可能从 controller 列表消失，`connections: null` 视作空列表，使用该请求的日志补证。
- 失败拨号日志也可能证明规则已经命中，但必须另列转发失败，不能混为一次成功。
- `192.0.2.0/24` 等文档网段可能被 GeoIP 归为 private，不能默认拿它验证 MATCH。
- 代理拒绝可表现为 HTTP 502；结合 REJECT 证据判断。匿名 API 的 401、重定向 302 和目标 404 分别解释，不随意改成失败或成功。
- 核对实际加载的规则和节点与候选一致。记录核心版本、输入 SHA-256、选定出口、测试目标及网络调整。

## 无人值守刷新

选择当前任务需要的模式：复用桌面会话适合已授权的一次性同步；服务器独立设备适合长期运行，但会占用账号设备名额。不要在普通刷新中静默更换身份。

提前续期窗口由项目决定。续期或失效恢复应有明确边界，限流、密码拒绝、设备上限和异常账号不能触发无限重试。批量获取途中认证失效时，用最终会话重新生成完整结果。

HTTP 429 应立即停止剩余线路请求。记录 Retry-After；只有当前任务已有明确的自动重试次数或时限时，才按该约束及服务端要求续跑，否则停止本批并说明恢复条件。不要换地址、账号或继续请求后续线路来规避限流。

首次批量失败时，把已有参数保存为私有的未完成检查点，不伪造“保留旧订阅”或宣称完整成功。没有明确接受部分结果的发布约定时，不用这份子集建立或覆盖正式缓存。完整目录真的减少与批次中断是不同情况，必须用目录数和逐项成败记录区分。

设备状态与文件发布原子写入，刷新并发要有锁。失败保留最后有效订阅，并单独更新错误状态；导出节点数采用当前接口结果和已确认的质量门槛，不固定某次采样数量。

## 发布到 VPS

只有当前任务已授权具体目标时才操作服务器。准备源码快照、原应用与缓存备份，以及失败恢复步骤。用实际服务用户和权限限制运行预发布，再检查原订阅链接、两家 token 隔离、未认证管理入口、正式刷新和定时任务。

订阅读取 token 与 provider 会话不是一回事。续期不应旋转客户端导入的读取链接；管理重置是独立动作。

最终 HTTPS 文件应能绑定到已验证候选的哈希。若上游正常更新导致节点或会话变化，重新验证新输入，不用旧结果覆盖新状态。

## 发布源码或 skill

使用干净目录和明确文件清单。源码、通用方法和合成测试可以公开；账号、密码摘要、设备状态、订阅链接、真实节点、截图、安装包、私有部署日志和开发者本机路径应留在原环境。

通用 skill 不写死某人的服务器、设备名称、SSH key、固定节点数或 Windows 路径。提供必要的参数和条件判断，保留客户端版本差异。只复制依赖明确、当前任务确实需要的代码或参考资料。
